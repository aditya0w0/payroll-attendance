# Anti-Slop Audit 021: Strict Multi-Login Hardening & Mandatory Admin Reset

- Date: 2026-11-20
- Context: Elimination of multi-login loopholes and enforcement of single-device lock with mandatory admin reset
- Scope: `src/app/api/auth/login/route.ts`, `src/lib/auth.ts`, `src/lib/attendance-scan-handler.ts`, `src/app/login/page.tsx`, and `prisma/seed.ts`

## 1. Multi-Login Vulnerability Analysis

Investigation revealed why multi-login was previously possible:

1. Unbound First Login Loophole:
   - In `src/app/api/auth/login/route.ts`, when an employee logged in without an active device registration (`!existingDevice || !existingDevice.isActive`), a session was issued, but `deviceRegistration` was never created or persisted.
   - Consequently, the account remained unbound indefinitely (e.g. Siti Rahma in seed data or any newly registered employee), allowing simultaneous logins across unlimited phones, desktops, and browsers without triggering single-device checks.

2. Lack of Active Session Fingerprint Validation:
   - In `src/lib/auth.ts` (`getCurrentUser`), active sessions were verified against expiration and user status, but not checked against the employee's currently authorized `deviceRegistration.deviceFingerprint`.
   - As a result, an old session from a previous or replaced device could continue to perform actions even after the account was reassigned or reset.

3. Attendance Scan Bypass for Unbound Accounts:
   - In `src/lib/attendance-scan-handler.ts`, device mismatch validation was guarded by `if (user.deviceRegistration)`. Accounts lacking an active device record skipped fingerprint verification entirely.

## 2. Hardening Measures Implemented

1. Immediate Auto-Binding on First Login:
   - In `src/app/api/auth/login/route.ts`, the first authenticated login (or login following an admin reset) now atomically binds the physical device (`deviceFingerprint`, `deviceName`, `platform`) in `deviceRegistration` (`isActive: true`, `status: "ACTIVE"`).
   - Invalidate any other active sessions and strictly lock the account to this physical terminal.

2. Strict Multi-Login Blocking (HTTP 423):
   - Any subsequent login attempt from a different device fingerprint triggers immediate rejection with HTTP 423 Locked (`DEVICE_NOT_AUTHORIZED`).
   - Automatically generates a pending `deviceUnlockRequest` visible in the Owner Console.
   - Clarified error message: Multi-login is prohibited; account is bound to another device and requires Owner/Admin reset.

3. Active Session Fingerprint Mismatch Invalidation:
   - In `src/lib/auth.ts` (`getCurrentUser`), employee sessions are checked against `session.user.deviceRegistration.deviceFingerprint`. If a session's fingerprint does not match the active registered device, the session is deleted immediately from the database and rejected.

4. Attendance Scan Guard:
   - In `src/lib/attendance-scan-handler.ts`, employee scans require an active `deviceRegistration` matching `deviceFingerprint`. Unbound or mismatched devices are rejected with HTTP 403.

5. Mandatory Admin Reset Workflow:
   - Switching devices requires an Owner to execute `RESET_DEVICE` in `/owner/devices` or `/owner/employees`.
   - Reset atomically marks the device as `REVOKED` and `isActive = false`, invalidates active sessions, and expires pending requests.
   - The employee is then allowed to bind their new device on their next login attempt.

6. Seed Data Hardening:
   - In `prisma/seed.ts`, Siti Rahma is now explicitly seeded with an authorized bound device (`Siti's Authorized Pixel 7`), ensuring all employees start in a secure, single-device state.

## 3. Automated Verification

- Authored `scripts/test-multi-login-prevention.ts` covering:
  - Authorized device login (HTTP 200).
  - Multi-login attempt from unauthorized second device (HTTP 423 Locked).
  - Stale session device mismatch rejection and automatic session deletion.
  - Mandatory Owner reset (`RESET_DEVICE`) workflow.
  - Re-binding of new replacement terminal upon post-reset login.
  - Strict blocking of the old device following replacement.
- Result: 22/22 tests passed.
