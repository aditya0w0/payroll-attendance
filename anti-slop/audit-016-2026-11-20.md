# Anti-Slop Audit Report #016

Date: 2026-11-20
Target: Dashboard Karyawan (/employee), Halaman Scan Presensi (/employee/scan), & Utilitas Deteksi Browser (src/lib/webview-detect.ts)
Audit Scope: Perbaikan false positive banner [WEBVIEW] pada peramban Chrome mobile, pemisahan deteksi in-app browser dengan pemeriksaan konteks keamanan HTTP (isSecureContext), serta penyediaan penanganan dan diagnostik akurat saat kamera & GPS diblokir oleh kebijakan peramban pada origin HTTP non-localhost.
Standard: Anti Slop Rules for AI Coding Agents (R-01 to R-40), antislop-ui, antislop-copywriting, antislop-human
Mode: Mode 2 (After Audit)

---

## Executive Summary

Menindaklanjuti kendala pengujian QA pada perangkat ponsel:
1. Pengguna membuka situs melalui Chrome Android di alamat IP Tailscale/LAN (`http://100.102.126.2:3000`).
2. Muncul banner peringatan: `Buka di Browser Utama (Safari / Chrome) [WEBVIEW]` padahal pengguna sudah membukanya di browser Chrome murni.
3. Tombol "Aktifkan" untuk Kamera dan Lokasi (GPS) tidak berfungsi atau tidak memunculkan prompt izin.

Penyebab Teknis Utama:
- Standar keamanan browser modern (W3C / Google Chrome) mewajibkan **Secure Context** (`window.isSecureContext === true`) untuk mengakses:
  1. API Kamera (`navigator.mediaDevices.getUserMedia`)
  2. API Lokasi GPS (`navigator.geolocation.getCurrentPosition`)
  3. API Biometrik / Passkey (`window.PublicKeyCredential`)
- Pada desktop, `http://localhost` dikecualikan dan dianggap aman secara default. Namun saat diakses dari ponsel melalui alamat IP non-localhost (`http://100.102.126.2:3000`), Chrome memperlakukannya sebagai **Insecure Origin** (ditandai ikon segitiga tanda seru pada bilah alamat).
- Akibatnya:
  - `window.PublicKeyCredential` menjadi `undefined`. Kode lama secara keliru menyimpulkan bahwa ketiadaan WebAuthn menandakan browser adalah `[WEBVIEW]`.
  - `navigator.mediaDevices` menjadi `undefined`, sehingga fungsi kamera macet dengan pesan menyesatkan "Buka situs di Safari atau Chrome".
  - `navigator.geolocation` langsung ditolak otomatis oleh Chrome tanpa menampilkan dialog izin.

Sesuai aturan antislop Mode 2, berkas kode tidak akan dimodifikasi sebelum nomor temuan disetujui pengguna.

## Detailed Findings

### Finding 1: False Positive Banner [WEBVIEW] & Pemisahan Konteks HTTP Insecure
- **Rule**: R-16 (Copywriting Accuracy & Precision), R-36 (Code Hygiene & Error Handling Integrity)
- **Tier**: Hard Gate
- **Priority**: HIGH
- **Location**:
  - `src/lib/webview-detect.ts`
  - `src/app/employee/page.tsx` (lines 237-254)
  - `src/app/login/page.tsx` (lines 338-348)
- **One-line reason**: Menampilkan label `[WEBVIEW]` dan menyuruh membuka Chrome padahal pengguna sudah di Chrome, karena ketiadaan WebAuthn disamakan dengan in-app browser padahal dipicu oleh origin HTTP non-secure.
- **Proposed Remedy**:
  1. Tambahkan pengecekan `isSecureContext: boolean` pada utilitas `detectInAppWebView`.
  2. Pisahkan secara tegas antara `isInApp` (WhatsApp, Telegram, IG, dsb.) dengan ketiadaan `isSecureContext`.
  3. Banner `[WEBVIEW]` hanya boleh aktif jika `isInApp === true`.
  4. Jika `!isSecureContext` (situs dibuka via IP HTTP), jangan tampilkan tuduhan WebView. Tampilkan kartu panduan diagnostik QA yang akurat bahwa browser mobile membatasi sensor pada koneksi HTTP biasa.

### Finding 2: Diagnostik & Penanganan Pemblokiran Kamera & GPS pada Akses HTTP Insecure
- **Rule**: R-14 (Component Craftsmanship), R-16 (Copywriting Accuracy), R-28 (State & Feedback Completeness)
- **Tier**: Hard Gate
- **Priority**: HIGH
- **Location**: `src/app/employee/scan/page.tsx` (lines 194-225, 270-278)
- **One-line reason**: Chrome Android memblokir silent `navigator.mediaDevices` dan `geolocation` pada origin HTTP non-localhost, sehingga klik tombol "Aktifkan" berulang kali tanpa memicu prompt izin.
- **Proposed Remedy**:
  1. Pada inisialisasi halaman scan dan pemanggilan fungsi sensor, deteksi jika `typeof window !== "undefined" && !window.isSecureContext`.
  2. Tampilkan status diagnostik yang tepat sasaran pada kartu sensor:
     "Kamera & GPS dibatasi peramban pada koneksi HTTP non-localhost. Gunakan HTTPS atau izinkan origin ini di chrome://flags."
  3. Berikan tombol bantuan ringkas dengan panduan solusi QA (menjalankan dev via HTTPS atau menyalin alamat `chrome://flags/#unsafely-treat-insecure-origin-as-secure`).
